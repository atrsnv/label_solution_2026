# Что уже готово в проекте Label ERP

## Backend

- Node.js + Express API.
- Prisma ORM.
- SQLite база данных.
- Миграции Prisma.
- Seed-скрипт с тестовыми пользователями.
- JWT-авторизация.
- Роли пользователей:
  - `ADMIN`;
  - `ARTIST`.
- Регистрация артиста по invite-токену.
- Логин пользователя.
- Получение текущего пользователя через `/me`.
- Middleware для проверки авторизации.
- Middleware для проверки ролей.
- Загрузка файлов через `multer`.
- Парсинг финансовых отчетов в форматах CSV и XLSX.

## Модели базы данных

- `User` - пользователи, артисты и администраторы.
- `Track` - музыкальные релизы.
- `Split` - распределение долей между артистами.
- `Report` - импортированные финансовые отчеты.
- `Earning` - начисления артистам.
- `Payout` - запросы на вывод средств.
- `Invite` - invite-ссылки для регистрации артистов.

## API авторизации

- `POST /api/auth/login` - вход пользователя.
- `POST /api/auth/register` - регистрация артиста по invite-токену.
- `GET /api/auth/me` - получение текущего пользователя.

## Admin API

- `GET /api/admin/dashboard/summary` - сводка для админ-панели.
- `GET /api/admin/artists` - список артистов.
- `POST /api/admin/artists` - прямое создание артиста.
- `POST /api/admin/artists/invite` - создание invite-ссылки.
- `GET /api/admin/artists/:id` - карточка артиста.
- `PATCH /api/admin/artists/:id` - редактирование артиста.
- `GET /api/admin/tracks` - общий реестр треков.
- `POST /api/admin/finance/import` - импорт финансового отчета.
- `GET /api/admin/finance/reports` - список импортированных отчетов.
- `GET /api/admin/finance/reports/:id` - детали отчета.

## Artist API

- `GET /api/artist/dashboard` - личная сводка артиста.
- `GET /api/artist/tracks` - список треков артиста.
- `GET /api/artist/invites` - приглашения в сплиты.
- `GET /api/artist/wallet` - кошелек артиста.
- `POST /api/artist/wallet/withdraw` - запрос на вывод средств.

## Tracks API

- `POST /api/tracks` - создание нового релиза.
- `GET /api/tracks/:id` - карточка трека.
- `POST /api/tracks/:id/splits/respond` - принять или оспорить сплит.

## Бизнес-логика

- У артиста есть индивидуальная доля лейбла `labelShare`.
- При создании трека доля лейбла фиксируется в самом треке.
- Доход по треку делится между артистами после вычета доли лейбла.
- Сплиты должны в сумме давать 100% от артистской части.
- Владелец трека автоматически принимает свой сплит.
- Приглашенные артисты могут принять или оспорить сплит.
- Если все сплиты приняты, трек получает статус `APPROVED`.
- Если кто-то оспорил сплит, трек получает статус `ERROR`.
- При импорте отчета создаются начисления артистам.
- Баланс артиста увеличивается на сумму начислений.
