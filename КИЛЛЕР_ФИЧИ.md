# Киллер-фичи для Label ERP

## 1. Прозрачная карточка расчета выплат

Артист видит не просто сумму, а полный расчет:

```text
Доход трека: 100 000 ₽
Доля лейбла: 30 000 ₽
Артистский пул: 70 000 ₽
Моя доля: 40%
К начислению: 28 000 ₽
```

Почему это сильная фича:
- артисты понимают, откуда взялась сумма;
- меньше споров с лейблом;
- ERP выглядит честной и прозрачной.

## 2. AI-разбор отчета дистрибьютора

После загрузки CSV/XLSX система автоматически объясняет:

- какие треки выросли;
- где просадка;
- кто топ-артист месяца;
- какие строки не удалось разнести;
- какие выплаты требуют внимания.

Пример:

```text
В июле доход вырос на 24%.
Главный драйвер — трек Northern Echo.
2 строки отчета не были обработаны: неизвестный трек и неподтвержденный сплит.
```

## 3. Умный матчинг треков

Если в отчете нет внутреннего `trackId`, система сама ищет совпадение:

- по названию трека;
- по артисту;
- по ISRC/UPC;
- по похожести строки.

Пример:

```text
Neon Rain → Masha Wave — 94% совпадение
City Light → City Lights — 89% совпадение
```

## 4. Антидубликаты отчетов

ERP проверяет, не был ли отчет уже импортирован:

- тот же период;
- тот же `transaction_id`;
- тот же трек;
- та же сумма;
- тот же источник.

Польза:
- защита от двойных начислений;
- меньше ручных ошибок;
- больше доверия к выплатам.

## 5. Автоматический dispute по сплитам

Система сама подсвечивает подозрительные сплиты:

- сумма долей не равна 100%;
- трек уже приносит доход, но сплит не подтвержден;
- артисту резко занизили долю;
- участник долго не принимает приглашение.

Пример:

```text
Риск: трек Midnight Drive уже имеет доход за 2025-07,
но один из участников не подтвердил сплит.
```

## 6. Artist Health Score

Рейтинг состояния артиста внутри лейбла:

- доход;
- рост;
- стабильность;
- количество релизов;
- количество фитов;
- риск конфликтов;
- активность выплат.

Пример:

```text
Masha Wave — 87/100
Рост дохода: высокий
Риск конфликтов: низкий
Активность релизов: стабильная
```

## 7. Прогноз выплат

ERP прогнозирует:

- доход следующего месяца;
- будущие выплаты артистам;
- нагрузку на баланс лейбла;
- артистов с самым быстрым ростом.

Пример:

```text
Ожидаемые выплаты за следующий месяц: 184 000 ₽
Вероятный топ-артист: Masha Wave
Прогноз роста: +17%
```

## 8. Честный баланс артиста

Баланс делится на понятные категории:

- начислено всего;
- доступно к выводу;
- ожидает подтверждения сплита;
- спорные начисления;
- уже выплачено.

Так артист видит не просто одну сумму, а реальное состояние денег.

## 9. Что изменилось после импорта

После загрузки отчета ERP показывает краткий итог:

```text
+124 000 ₽ начислено
+18% к прошлому месяцу
3 новых трека в отчете
2 строки требуют ручной проверки
1 артист впервые вышел в топ
```

Это хорошо работает на демо: загрузили файл — сразу получили понятный результат.

## 10. Explainable DataLens

DataLens показывает графики, а ERP рядом объясняет их человеческим языком:

```text
Рост в июле связан с треком Northern Echo.
Основной источник роста — Яндекс Музыка.
Доход по треку вырос на 42%.
```

## Что лучше сделать первым

Самые сильные фичи для демо:

1. Прозрачная карточка расчета выплат.
2. AI-разбор импорта отчета.
3. Умный матчинг треков.
4. Антидубликаты отчетов.

Если времени мало, лучше начать с **прозрачной карточки расчета выплат**. Она понятна жюри, легко демонстрируется и напрямую решает боль артистов.
